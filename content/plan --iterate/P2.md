A spawn of [[P1]].

Docker is basically doing the Uvicorn run for you, so you don’t have to run it separately when you use Docker.

**What the Docker section in README.md does**  
It gives you the two commands to build and run the backend as a container:

1. docker build -t backend .
2. docker run -p 8080:8080 backend

That means Docker will build an image and then run it, exposing the app on port 8080 inside the container and mapping it to 8080 on your machine.  

**What the Dockerfile does**
It defines how the backend container is built and started:

1. Uses python:3.11-slim as the base image.
2. Installs system packages needed for PDF/image/DOCX processing (LibreOffice, libgl, libcairo, etc.).
3. Installs uv and Python dependencies from pyproject.toml.
4. Copies the app code.
5. Creates a non-root user.
6. Exposes port 8080.
7. Starts the app with:  
    uvicorn app.main:app --host 0.0.0.0 --port 8080

So **the Docker container already runs Uvicorn for you**.  

**To answer to your question:**  

Yes. If you’re running via Docker, you do **not** need to manually run uvicorn yourself. Docker will start it using the CMD in the Dockerfile. 

You only run uvicorn directly when you’re running the app locally without Docker.
